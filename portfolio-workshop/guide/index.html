作品を並べた1ページのポートフォリオサイトを作ろう

Claude デスクトップアプリの「Code」で作る ポートフォリオ制作ワークショップ

対象：コードを書いたことがない方（Claude Code をはじめて使う方も歓迎）
使うもの：Claude デスクトップアプリ（Mac / Windows）の Code（Claude Code）・有料プラン
作るもの：自己紹介と作品を並べた 1ページのサイト（index.html というファイル1つ）
公開のしかた：別紙「Netlify で公開する」を使います。この手順書は 「作る」ところまで を扱います
※ 画面写真は Mac のものです。Windows でも操作は同じです。

0. このワークショップについて

コードは一行も書きません。 やることは、Claude に日本語で「こう作って」とお願いするだけです。

今日いちばん覚えて帰ってほしいのは、この順番です。

  1. 載せる中身を先に、文章（設計書）に書き出す
  2. その設計書を Claude Code に読ませて、サイトの形にしてもらう
  3. できたサイトを見ながら、色や並び順を「頼むだけ」で直す
🤔 なぜ、いきなり「サイトを作って」と頼まないのか
チャットで思いつくまま伝えると、作品の抜けや、書き忘れた連絡先が出ます。先に1枚の設計書にまとめておけば、Claude はそれを読んで全部を漏れなく並べられます。さらに、あとで作品が増えたときも設計書に1つ足して「反映して」と頼むだけで更新できます。
デザインを作り直しても中身は残るので、「中身」と「見た目」を別々に育てられるのが、この方式のいちばんの利点です。

完成イメージ（講師の見本）

自己紹介・作品カード・連絡先を1ページに並べたサイトです。今日はこの「器」を自分の内容で作ります。

今日のゴール

  • 自分のパソコンの portfolio フォルダに index.html ができて、ダブルクリックで自分のサイトが開く
  • 色・並び順・文言を、お願い文を貼るだけで直せる
  • 別紙の公開手順に進める状態になっている（公開すると URL 1本で自己紹介が済む）
📗 用語
ポートフォリオ：これまで作ったもの・できることをまとめて見せるための作品集。応募フォームやプロフィール欄に URL を貼って使います。
index.html：Web ページの本体となるファイル。ブラウザはこの名前のファイルを「そのフォルダの表紙」として最初に開きます。だからサイトの本体はこの名前にします。
Claude Code（Code）：Claude デスクトップアプリの中の、あなたのパソコンのフォルダに本物のファイルを作ってくれるモード。チャットは画面の中だけですが、Code はフォルダに index.html を実際に保存します。

1. 準備するもの

  • Claude デスクトップアプリ（インストール＆ログイン済み・有料プラン）
  • 配布した portfolio フォルダ（手元に無い方は、この章の中で自分で作れます）
  • 顔写真かアバター画像（無くても作れます。イラストでも OK）
  • 作品の画像（スクリーンショットなど。無い作品は文章だけでも OK）
  • 載せたい リンク（公開 URL・SNS・GitHub など。無くても OK）
🔑 アプリのインストールとログインは開始前にすませてください。
分からない場合はファシリテーターに声をかけてください。

1-1. 作業フォルダをデスクトップに置く

配布した portfolio フォルダを、デスクトップにそのままコピーします。中身はこの2つです。

portfolio/
├── portfolio.md   ← 設計書。ここに「載せたいこと」を書く
└── images/        ← 顔写真・作品の画像を入れる
🤔 なぜフォルダを1つ決めるのか
Code は「このフォルダの中でファイルを読み書きしてよい」と決めてから動きます。フォルダを決めないと、設計書がどこにあるのか、index.html をどこに作ればよいのかが決まりません。
デスクトップに置くのは、あとでフォルダを選ぶときに迷わないためと、公開するときにアップロードするフォルダをすぐ見つけられるためです。

配布フォルダが手元に無い方：デスクトップで右クリック →「新規フォルダ」（Windows は「新規作成」→「フォルダー」）で portfolio を作り、その中にもう1つ images フォルダを作ってください。portfolio.md は、巻末の 付録A の内容を「テキストエディット」（Windows は「メモ帳」）に貼り付けて、portfolio.md という名前で portfolio フォルダに保存すれば同じものになります。

⚠️ フォルダ名とファイル名は 半角の英数字 にしてください（portfolio・face.jpg・work1.png のように）。
公開したとき、画像のファイル名は そのまま URL の一部になります。日本語や全角のファイル名は、環境によって文字化けしたり画像が表示されなかったりする原因になります。

1-2. 画像を images フォルダに入れる

  • 顔写真・アバター：スマホで撮ったもので十分です。顔出しに抵抗があれば、イラストやアバター画像でかまいません。
  • 作品の画像：Web サイトなら画面のスクリーンショット、アプリなら画面写真、画像作品はそのもの。文章や記事の作品は画像が無くても大丈夫です。
  • 入れたら、ファイル名を控えておきます（あとで設計書に書きます）。
📗 スクリーンショットの撮り方
Mac：⇧ shift + ⌘ command + 4 を押し、撮りたい範囲をドラッグ → デスクトップに画像ファイルとして保存されます。
Windows：Win + Shift + S を押し、撮りたい範囲をドラッグ → 画面右下の通知を押すと保存できます（保存先は「ピクチャ」→「スクリーンショット」）。
撮れたファイルの名前を work1.png のような半角英数字に変えてから images に入れると、あとで指定しやすくなります。

2. 載せる中身を決めて、設計書 portfolio.md に書く（ここが一番大事）

portfolio フォルダの中の portfolio.md を開きます。ダブルクリックで開かないときは、右クリック →「このアプリケーションで開く」→ テキストエディット（Windows は メモ帳）を選びます。VS Code などのエディタがある方はそれで開いてください。

📗 用語
Markdown（.md）：# で見出し、- で箇条書きを表す、ただの文字だけの書き方です。特別なソフトは要りません。Claude はこの書き方を正確に読めるので、設計書に向いています。

設計書は 5つの箱 に分かれています。書けるところだけで大丈夫です。空欄はサイトに載りません。

箱書くことなぜ必要か
1. あなたのこと表示名・肩書きのひとこと・自己紹介（3〜5行）・顔写真のファイル名サイトの一番上に出る「顔」。見た人が最初に読む場所なので、何をしている人かが1行で伝わる言葉を入れます
2. 作品作品名・種類・ひとこと・くわしく・使ったもの・画像のファイル名・リンク・時期今日の主役。載せたい順に書きます（上に書いたものがサイトでも上に来ます）
3. できること・使える道具ツール名やスキルを箇条書き作品だけでは伝わりにくい「対応できる範囲」を補います
4. 連絡先・リンクメール・SNS・GitHub などサイトの目的は「連絡してもらうこと」。1つでもあれば十分です
5. サイトの雰囲気色の好み・雰囲気・参考サイトClaude がデザインを決めるときの手がかり。空欄なら Claude におまかせになります

作品が少ない・まだ無い方へ

「作品」は、お金をもらって作ったものだけではありません。次のようなものも立派な作品です。

  • 学習の成果物：コースの課題で作ったもの、ワークショップで作ったゲームやアプリ、コンペに出した作品
  • 練習で作ったもの：自分用の家計簿、業務の自動化スクリプト、Canva で作ったバナー
  • 文章：note や SNS の記事、社内向けに書いたマニュアルやプロンプト集（社外に出してよいものだけ）
  • これから作るもの：「制作中」として1枚書いておく（完成したら差し替える）

1つでも十分です。 今日の目的は「完成した作品集」ではなく、これから作ったものを足していける器と URL を手に入れることです。

書くときのコツ

  • 数字を入れる：「毎週使っている」「上司の確認時間が半分に」「7ステップで完成」など、具体的な数字や変化があると伝わります
  • 誰に見せるかを思い浮かべる：応募先の担当者・SNS で知り合った人・知人。その人が知りたいことから書きます
  • きれいな文章でなくて OK：箇条書きや話し言葉のままで大丈夫です。整えるのは Claude の仕事です
⚠️ 公開される前提で書いてください。
住所・電話番号・生年月日は載せません。本名を出すかニックネームにするかは自分で決めます。
勤務先の名前や、仕事で作ったものは 社外に出してよいか を確認してから載せます。顔写真も同じです。
あとから直せるので、迷ったものは今日は空欄にしておきましょう。

記入例

配布フォルダの 記入例_ペン太 に、事務職で生成AI を学習中の「ペン太」さんの設計書と、そこから作ったサイトを入れてあります。「作品」の書き方は、たとえばこうです。

### 作品1
- 作品名：今月の家計簿アプリ
- 種類：学習の成果物（Webアプリ）
- ひとことで何か（1行）：収入・支出・残りが一目でわかる、自分用のシンプルな家計簿
- くわしく（2〜4行）：Excelで管理していた家計簿を、スマホでも見やすいWebアプリにしました。
  Claude Codeに日本語で頼みながら、分類の色分けと「残り」の自動計算を追加。
- 使ったもの：Claude Code、HTML / CSS / JavaScript
- 画像のファイル名：kakeibo.png
- リンク：
- 作った時期：2026年8月

書き終えたら 保存（⌘S / Ctrl+S）します。保存していないと、Claude は古い内容を読んでしまいます。

3. Claude の「Code」を開いて、フォルダを選ぶ

3-1. 「Code」に切り替える

アプリ左上の 「ホーム」／「Code」 の切り替えで、「Code」 をクリックします。

3-2. 作業フォルダを選ぶ

入力欄のすぐ上に、フォルダのアイコンが付いた小さなボタンがあります（ローカル の右どなりです）。 これをクリック →「フォルダを開く…」を選びます。

ファイルを選ぶ画面が開くので、デスクトップ → portfolio の順にたどって、portfolio フォルダを選んだ状態で 「開く」 を押します。

🤔 なぜ「フォルダ」を選ぶのか（ファイルではなく）
Claude Code は、選んだフォルダの中にある portfolio.md と images を読み、同じ場所に index.html を作ります。
ファイル1つを渡す方式だと、画像フォルダが見えず、作った index.html の置き場所も決まりません。

3-3. 「信頼しますか？」と聞かれたら

初めてのフォルダでは、下のような確認が出ます。押す前に、ダイアログに出ているフォルダの場所を見てください。 いちばん最後が portfolio、その1つ手前が Desktop（デスクトップ） になっていれば OK です。 違うところが出ていたら「キャンセル」して、もう一度フォルダを選び直してください。 確認できたら「ワークスペースを信頼する」を押して進みます。

⚠️ これは「このフォルダの中で、ファイルを読み書きしたり動かしたりしていいですか？」という確認です。
信頼すると、Claude がこのフォルダの中で自分でファイルを作ったり書き換えたりできるようになります。
自分が作った・中身が分かっているフォルダのときだけ信頼してください。
※ 一度信頼したフォルダでは、この確認は出ません。出なくても失敗ではありません。

3-4. 選べたか確認する

入力欄の上のボタンが portfolio になっていれば成功です。

💡 入力欄の左下のボタンが 「手動」（古いバージョンでは「編集を承認」）か 「自動」 なら、そのまま進めます。
ここが 「プラン」 になっているとファイルが1つも作られません。「手動」か「自動」に切り替えてください。
「手動」のときは、Claude がファイルを作る前に「はい／許可」を聞いてきます。内容を見て「許可」を押せば進みます。
📗 ターミナル版（コマンド入力）で参加する方へ
ターミナルで cd ~/Desktop/portfolio（Windows は cd %USERPROFILE%\Desktop\portfolio）と入力して Enter、続けて claude と入力して Enter で起動します。
あとは、この手順書のお願い文をそのまま貼るだけで同じように進められます。「信頼しますか？」の確認も同じように出ます。

4. お願い①：サイトを作ってもらう

🎯 ゴール：portfolio フォルダに index.html ができて、ダブルクリックで自分のサイトが開く

💬 貼り付けるお願い（このまま全部コピーして貼ります）

このフォルダの portfolio.md を読んで、自己紹介と作品を並べた1ページのポートフォリオサイトを index.html という名前で作ってください。

守ってほしいこと：
- HTML・CSS・JavaScript は index.html の1ファイルにまとめる（外部のライブラリやCDNは使わない）
- 画像は images フォルダのものを使う
- スマホでもパソコンでも見やすいレイアウトにする
- portfolio.md で空欄の項目はサイトに表示しない
- 作品は portfolio.md に書いた順番で並べる
- 「5. サイトの雰囲気」に書いた希望を色とデザインに反映する

できあがったら、確認のしかたを教えてください。

画面下の入力欄に貼り付けて、Enter で送信します。

🤔 お願い文の「守ってほしいこと」は何のためか
1ファイルにまとめる：公開するときに index.html と images だけをアップロードすればよくなり、「別のファイルが足りなくて表示が崩れる」事故を防げます。
外部のライブラリを使わない：インターネット上の部品に頼ると、その部品が変わったり止まったりしたときにサイトごと壊れます。
空欄は表示しない：「メール：」のような空の見出しが残ると、未完成に見えてしまいます。
書いた順番で並べる：見せたい順は、あなたが決めるものです。Claude に勝手に並べ替えさせません。
📗 用語
HTML / CSS / JavaScript：Web ページを作る3種類の書き方です。HTML は「何を載せるか」（文章・画像）、CSS は「どう見せるか」（色・配置）、JavaScript は「どう動くか」（クリックしたときの反応）を担当します。今日はすべて Claude が書きます。

送信すると「作成中」や「考え中」と表示されます。ここで数分かかります。Claude はまず portfolio.md と images の中身を読み、それから index.html を書きます。

「許可しますか？」と聞かれたら、内容を見て 「一度だけ許可」（または「許可」）を押してください。「手動」のときは、Claude が画像の大きさを調べたりファイルを作ったりする前に、このように一つずつ確認してきます。押すまで Claude は待っていますので、止まって見えたらこの確認が出ていないか見てください。

🤔 なぜ毎回聞かれるのか
「手動」は、Claude がパソコンの中で何かを実行する前に必ず人の確認を取る設定です。今日のように中身の分かっているフォルダなら「自動」にしても構いませんが、初めてのうちは何をしようとしているかが見える「手動」のほうが安心です。

👀 うまくいくと：portfolio フォルダに index.html ができ、Claude が「ダブルクリックで開けます」のような案内を返します。右側にアプリ内のブラウザが開いて、サイトが表示されることもあります。

✅ 見てみよう：portfolio フォルダの index.html をダブルクリックすると、いつものブラウザで開きます。

⚠️ AIなので、出来上がりは人によって違います。 隣の人と色や配置が違っていて正常です。
気に入らないところは、次の章で「頼んで直す」ので心配いりません。

🔧 ダメなとき

  • 画像が出ない → portfolio.md に書いたファイル名と、images の中のファイル名（拡張子 .png .jpg まで）が同じか確認。違っていたら直して 画像のファイル名を直しました。index.html に反映してください。
  • 途中で止まった → 「作成中」の表示が消えているのを確かめてから 続きを作ってください。
  • index.html ができない → 左下が「プラン」になっていないか確認（3-4）

5. お願い②：見ながら直す（色・並び順・文言）

ここからは 「見て → 頼んで → 再読み込み」 の繰り返しです。同じ会話に続けて貼っていきます（新しく開き直さないでください）。

直すときの3つのコツ

コツどういうこと？例
① 一度にひとつだけ頼む欲張ると意図と違う直し方をされやすい。1回のお願い＝1か所×「色も並びも文章も全部変えて」 → 〇「まず見出しの色だけ変えて」
② 見た目の言葉で場所を伝えるHTML の言葉は不要。画面のどこかを言えば通じる〇「作品の2番目のカードの説明文を、2行くらいに短くして」
③ 直したら再読み込みブラウザは開いた時点の内容を表示したまま。index.html が書き換わっても自動では変わらない直してもらったら ⌘R（Windows は Ctrl+R）

そのまま貼れるお願い文の例

見出しと差し色を、水色ではなく緑系に変えてください。
作品の並び順を変えて、「スペースインベーダー」を一番上にしてください。
自己紹介の文章を、もう少し短く3行くらいにまとめてください。内容は変えないでください。
顔写真をもう少し大きく、丸く切り抜いて表示してください。
「できること」の項目を、タグのような小さな四角で横に並べてください。
連絡先の下に、メールを送るボタンを付けてください。
スマホの幅で見ると作品カードの文字がはみ出します。スマホでは1列に並ぶように直してください。
その変更は取り消して、直前の状態に戻してください。

たとえば「見出しと差し色を緑系に」と頼むと、こう変わります。中身は同じまま、色だけが変わっていることを確かめてください。

直し終わると、Claude は 何をどう変えたか を説明してくれます。思っていたのと違えば、その説明を手がかりにもう一度頼みます（例：「背景の薄い色は水色のままにして」）。

⚠️ 直してもらったのに変わらないときは、まず再読み込み。 ブラウザのタブを開いたままだと前のままです。
⌘R（Windows は Ctrl+R） を押してから、もう一度見てください。アプリの中のプレビューも同じです。
📎 気に入った状態になったら、控えを1つ。 index.html をコピー＆ペーストして複製しておくと、この先で崩れても必ずここに戻れます。
🎉 ここまでで「自分のポートフォリオサイト」が手元にできました。 ファイルはすでにあなたのパソコンにあります。保存の作業はいりません。

6. 雰囲気をまるごと変える（どんな指示で、どんなサイトになるか）

色や文言を1か所ずつ直すだけでなく、「雰囲気」をまるごと指定して作り直すこともできます。 講師の見本は、同じ設計書（portfolio.md）と同じ画像から、Claude に次のようなお願いをして5つのパターンに作り分けたものです。 中身は5つとも同じで、変わっているのは見た目と語り口だけです。気に入った方向のお願い文を、自分の言葉に直して使ってください。

🤔 なぜ「雰囲気」は設計書と分けて指示するのか
設計書には「何を載せるか」だけを書いておき、見た目は別のお願いで指定します。こうしておくと、中身を失わずに何度でも衣替えができ、逆に作品を足すときも見た目が崩れません。
お願い文の最初に「載せる内容・作品の順番・リンク・数字は変えない」と念を押すのがコツです。これが無いと、Claude が気を利かせて文章や数字まで書き換えることがあります。
⚠️ 別バージョンは 別の名前（index-humor.html など）で作ってもらうと、元の index.html が残ります。公開するときは、気に入ったほうを index.html に改名して使います。

パターン1：ミニマル（白地に差し色1つ）

設計書の「5. サイトの雰囲気」にこう書いて、4章のお願い①をそのまま貼ったもの。

- 色の好み：白地に、紫のアクセントを 1 色だけ
- 雰囲気：余白を広く取ったシンプルで今風。作品カードを主役に
- 参考にしたいサイト：見出しを大きく・写真は丸く・実績の数字は帯にして横に並べる

パターン2：ユーモア・親しみ

index.html を、雰囲気だけ変えた別バージョン index-humor.html として作ってください。
載せる内容・作品の順番・リンク・数字は変えないでください。

方向性はユーモアと親しみ。砕けた一人称の語り口にして人柄を見せてください（ただし実績の数字や信頼感は崩さない）。
色は暖色（オレンジ・コーラル・クリーム）。有機的な形や手描き風の下線、傾いたステッカー風のバッジ、吹き出しの自己紹介で遊んでください。
ヒーローは丸い顔写真のまわりに、実績のバッジを浮かべる構成に。作品カードは「シールを貼ったノート」のような雰囲気で。
絵文字は使わず、言葉づかいと色とあしらいで親しみを出してください。

パターン3：ダーク・モダン

index.html を、雰囲気だけ変えた別バージョン index-dark.html として作ってください。
載せる内容・作品の順番・リンク・数字は変えないでください。

黒〜濃紺の地に、差し色は1色だけ（黄色）。画面幅いっぱいに迫る巨大な名前の文字（RYUJI MIYAZAKI）で個性を出してください。
実績の数字は、大きな数字と小さなラベルを横に並べた帯にして、均等なタイルにはしないでください。
作品カードは暗いカードにうっすら光る差し色。マウスを乗せると浮く。経歴は差し色の点と線のタイムライン。
暗い背景でも本文が読めるコントラストを確保してください。

パターン4：エディトリアル・モノクロ

index.html を、雰囲気だけ変えた別バージョン index-editorial.html として作ってください。
載せる内容・作品の順番・リンク・数字は変えないでください。

雑誌の誌面のような白黒と罫線。巨大な英字の名前と、明朝体（セリフ体）の日本語見出し。余白をたっぷり取ってください。
作品は「番号付きの罫線リスト（作品名・種別・年・リンク）」を主役にして、選んだ数点だけ大きな画像で見せる構成に。
写真はモノクロに統一。差し色を使うなら1色をごく少量。動きは控えめに。

パターン5：ビジネス・信頼

index.html を、雰囲気だけ変えた別バージョン index-business.html として作ってください。
載せる内容・作品の順番・リンク・数字は変えないでください。

読む相手は企業の研修担当者や、業務委託の発注者です。紺とベージュを基調に、金や朱の差し色を少量。明朝体（セリフ体）の大見出しで落ち着いた信頼感を出してください。
ヒーローには「提供できること」を3枚のサービスカードで明示し、その下に実績の数字を1行の帯で。
作品カードは白いカードに細い罫線と控えめな影。経歴は会社ごとのカード。
連絡先には「ご相談の流れ（ヒアリング → ご提案 → 実施）」を添えて、メールのボタンを目立たせてください。文体は敬体で簡潔に。
💡 お願い文の作り方（共通の型）
①「別の名前で作って」＋「中身は変えないで」 → ②誰に見せたいか・どんな印象にしたいか → ③色（2〜3語） → ④形や質感（丸い・罫線・ステッカー・光る など） → ⑤見出しの書体（ゴシック／明朝）と語り口。
5つ全部を書かなくても大丈夫です。②と③だけでも、雰囲気はかなり変わります。

7. 公開する（別紙へ）

公開の手順は、別紙 「Netlify で公開する」 に沿って進めます。ここでは、公開すると何が起きるかだけ押さえておきます。

  • portfolio フォルダ（index.html と images）を Netlify という公開サービスにアップロードすると、あなた専用の URL が発行されます
  • その URL を開くと、世界中のどこからでも今日作ったサイトが表示されます
  • URL は、応募フォームやプロフィール欄に そのまま貼って使えます
🤔 なぜ index.html をダブルクリックで開けるのに、公開の作業がいるのか
ダブルクリックで開いているのは、あなたのパソコンの中のファイルです。他の人のパソコンにはそのファイルが無いので、URL を送っても開けません。
インターネット上の置き場所（サーバー）にファイルを置いて、誰でも取りに来られる状態にするのが「公開」です。

公開する前の確認

  • 住所・電話番号・生年月日など、載せたくない情報が入っていない
  • 顔写真・勤務先名・仕事で作ったものは、出してよいと確認済み
  • リンクを1つずつクリックして、正しいページが開く
  • ブラウザの幅を狭くして（またはスマホで）、崩れていない
  • portfolio.md（設計書）は公開しなくてよい。アップロードするのは index.html と images だけでもよい

8. あとから育てる 🌱

作品が増えたら、こう更新します。

  1. portfolio.md に 作品の塊を1つ足す（「### 作品」をコピーして書く）。画像があれば images に入れる
  2. Claude の Code で 同じ portfolio フォルダ を開き、次のお願いを貼る
  3. 公開し直す（別紙の手順）
portfolio.md に作品を1つ足しました。index.html に反映してください。
デザインは今のまま変えないでください。
💡 これが、設計書を先に書く方式の良いところです。サイトを作り直すのではなく、設計書に足すだけ。
デザインを変えたくなったときも、portfolio.md はそのままで「雰囲気を落ち着いた紺色に変えて」と頼めば、中身を失わずに衣替えできます。

9. うまくいかないとき（そのまま貼れる言葉）🔧

こまりごとやること
直してもらったのに、さっきと同じまままずブラウザのタブで ⌘R / Ctrl+R（再読み込み）。頼み直す前に、必ずこれを試す
画像が表示されない（枠だけ・壊れたマーク）portfolio.md のファイル名と images の中のファイル名を見比べる（大文字小文字・拡張子まで同じか）。直したら 画像のファイル名を直しました。反映してください。
index.html ができない入力欄左下が「プラン」になっていないか確認。「手動」か「自動」にして index.html を作ってください。
「許可しますか？」で止まっている内容を見て「許可」を押す。押すまで Claude は待っています
作るのが途中で止まった「作成中」「考え中」の表示が消えているか確認。消えていたら 続きを作ってください。
変な方向に変わってしまった直前の変更を取り消してください。 それでも直らなければ、取っておいた控えを index.html に戻す
いっぺんに頼んだら崩れたひとつずつに分けて頼み直す（コツ①）
フォルダを間違えた入力欄の上のフォルダのボタンから選び直す。分からなければ左上の「新規」で会話を作り直し、3章のやり方でもう一度選ぶ
設計書を直したのに反映されないportfolio.md を保存したか確認（⌘S / Ctrl+S）。保存してから portfolio.md を更新しました。反映してください。
利用の上限に達しました と出た手を挙げてください。そこまでのファイルはフォルダに残っています（消えません）

10. ファシリテーターの方へ 🧑‍🏫

事前準備

  • 必ず一度、自分で最後まで通しで作る（配布フォルダ → お願い① → お願い②。返り方と待ち時間の感覚をつかむ）
  • 当日の実機で UI（Code タブ・フォルダ選択・信頼ダイアログ・左下のモード名）を確認（バージョンで文言が変わります）
  • 講師の見本サイト（見本_宮﨑竜治/index.html）と記入例（配布/記入例_ペン太）を、冒頭で実際に開いて見せる
  • 開始前に、全員の ログイン済み／有料プラン／Code タブが見える ことを確認
  • 開始前に、全員の入力欄左下を「手動」か「自動」にそろえる（「プラン」だとファイルが作られません）
  • 参加者に配布フォルダをデスクトップに置かせ、画像を入れさせておくと、当日の立ち上がりが速い

進行のコツ

  • 山場は 2章（設計書を書く）。ここに一番時間を使う。「1つでいい」「空欄でいい」を何度も言う
  • お願い①の生成待ちは実況で埋める（「いま portfolio.md を読んでいます」「index.html を書き始めました」）と「止まった？」の不安を防げる
  • 出来上がりは人によって違う。「隣と違って OK」と最初に伝える
  • お願い②は「見る → 頼む → ⌘R」の3拍子。再読み込みを毎回声に出す
  • 公開（別紙）に進む前に、7章の「公開する前の確認」を全員で読み合わせる

つまずきどころ Top3

  1. フォルダ選択と信頼ダイアログ＋許可ダイアログ → 最初の関門。全員そろってから次へ進む
  2. 画像のファイル名の食い違い → portfolio.md の記載と images の実物が違う（全角・拡張子・大文字小文字）。「ファイル名をコピーして貼る」を勧める
  3. 再読み込みし忘れ → お願い②に入る前に「直したら ⌘R」を伝えておく
